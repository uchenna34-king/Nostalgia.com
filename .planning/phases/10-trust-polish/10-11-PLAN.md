<objective>
Ship SEO-01 for the Nostalgia storefront: per-page metadata, structured data, a sitemap,
and a robots policy — the discoverability layer of Phase 10.

This plan delivers, per D-04 and D-14:
- `lib/seo.ts` — a pure, Prisma-free `buildProductJsonLd` (schema.org Product/Offer,
  `aggregateRating` only when reviews exist) plus a `<`-escaping serializer, unit-tested by
  the Wave-0 `tests/seo.test.ts` scaffold.
- `generateMetadata` (+ Open Graph / Twitter) on the three dynamic routes — PDP, `/shop`,
  collection detail — and a Product JSON-LD `<script>` on the PDP.
- `app/sitemap.ts` and `app/robots.ts` using Next.js `MetadataRoute` types.

Purpose: Search engines and social scrapers can index the storefront correctly and render
rich product results, closing the last discoverability gap before go-live.

Output: `lib/seo.ts`, `app/sitemap.ts`, `app/robots.ts`, plus metadata/JSON-LD additions to
the PDP, shop, collection, and root-layout files.

**Scope boundaries (do NOT recreate work owned by sibling plans):**
- Static metadata on the `/shipping` and `/returns` policy pages is owned by **10-08** (each
  page ships its own `metadata` export). This plan only *references* those routes in the
  sitemap — it does not touch or create the policy pages.
- The `product.rating` field and the `lib/products.ts` rating merge are owned by **10-03**.
  This plan consumes `product.rating`; it does not compute ratings.
- Root/home default metadata already lives in `app/layout.tsx`; this plan only *adds*
  `metadataBase` there (for OG/Twitter relative-URL resolution) — it does not rewrite the
  existing title/description.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| owner-entered product content → inline JSON-LD `<script>` | Product `name`/`description` are serialized into a `dangerouslySetInnerHTML` script tag; a `</script>` sequence in that text could break out of the script context. |
| crawler → sitemap/robots | Public endpoints that enumerate site URLs and declare crawl policy; must not leak private routes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-11-01 | Tampering / Injection | PDP JSON-LD `<script>` (`lib/seo.ts` serializer + render site) | medium | mitigate | Escape every `<` to its `<` form on the stringified JSON-LD payload (RESEARCH Pattern 4 / Pitfall 5) — defense in depth even though product content is owner-entered; covered by `tests/seo.test.ts`. |
| T-10-11-02 | Information Disclosure | `app/robots.ts` + `app/sitemap.ts` | low | mitigate | robots disallows `/admin`, `/api`, `/account`, `/checkout`; sitemap enumerates only public product/collection/policy/home URLs — no admin or account paths. |
| T-10-11-03 | Spoofing / Tampering | sitemap/robots absolute base URL | low | mitigate | Resolve base from `NEXTAUTH_URL` env (never the request `Origin`), matching the `app/api/checkout/route.ts` convention, so crawl URLs cannot be poisoned via a forged Host/Origin header. |

**Package legitimacy:** This plan performs no `npm`/package installs (jest-axe is installed by
10-01, `@vercel/analytics` by 10-09). No package-legitimacy checkpoint required.
</threat_model>
