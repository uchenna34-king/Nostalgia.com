# Phase 12 — UI Design Contract

> Visual and interaction contract for multi-currency payments: the nav currency toggle, the dual-render `<Money>` price, the checkout delivery-address form and payment notices, shipping/free-delivery copy, the shop price filter, the admin pricing/settings/order surfaces, and the account + email order displays. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Auto mode: no owner questions were asked; every product decision is locked in `12-CONTEXT.md` and every visual detail is resolved from `DESIGN.md`, `app/globals.css`, `tailwind.config.ts` and the live components. Every assumption is recorded in the final section.

**Source-of-truth order (read this first):**
1. `DESIGN.md` + `app/globals.css` + `tailwind.config.ts` + the live components (authoritative).
2. `12-CONTEXT.md` (locked behaviour) and `12-RESEARCH.md` Pattern 5 (the `<Money>` + before-paint script mechanism).
3. Phase 10/11 UI-SPECs: reused for structure, voice, 44px targets and status-pill rules only. **Their palette and type are stale** (cream `#F4EEE4`, sepia `#A6552F`, Fraunces, `font-black` 900): the product is now **black and white only**, Bodoni Moda at weight 400 for the voice, Inter for everything read. The tokens `cream`, `ink`, `sepia*` still exist in code but resolve to neutrals (see Color). Ignore any hex or font from the older specs.

**Scope fence:** one new component pair (`Money`/`CurrencySymbol`), one new control (`CurrencyToggle`), one new form (checkout address), one new admin page (`/admin/settings`), and edits in place to existing surfaces. No new visual language, no new tokens, no new colours, no new animation.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled Tailwind; `components.json` absent; shadcn gate not applicable, carried forward from Phases 1-11) |
| Preset | not applicable |
| Component library | none (bespoke Tailwind + `@layer components` classes: `.btn-primary`, `.btn-outline`, `.eyebrow`, `.kicker`, `.container-x`, `.link-underline`, `.glass-panel`) |
| Icon library | none (inline SVG only). **This phase adds no icons**: `₦` and `$` are text glyphs |
| Font | **Bodoni Moda** (`font-serif`, `--font-bodoni`): wordmark, headlines, product names, weight 400 only. **Inter** (`font-sans`, `--font-inter`): all reading text, controls, labels, **and every price**. Vendored in `app/fonts`, loaded via `lib/fonts.ts` |

**Font coverage finding (verified by parsing the vendored files' cmap tables, 2026-10-13): neither `Inter-latin-normal.woff2` nor `BodoniModa-latin-normal.woff2` contains the naira sign U+20A6.** `$`, `£`, `€`, `·`, `–` are present; `₦` is not (Google's *latin* subset ends before U+20A0-20AB; `₦` lives in *latin-ext*). Unfixed, every naira price would render its `₦` from a random system fallback face with different weight and metrics, and inside any `font-serif` price it would fall through Didot/Georgia to a generic serif. Contract:
- **D-FONT-1:** vendor Inter's **latin-ext** variable subset as `app/fonts/Inter-latin-ext-normal.woff2` and register it in `lib/fonts.ts` as a second `localFont` with `variable: "--font-inter-ext"`, then append it to `fontFamily.sans` directly after `var(--font-inter)` in `tailwind.config.ts`. Per-glyph fallback then lands `₦` in Inter. No Bodoni extension file is needed because of D-FONT-2.
- **D-FONT-2:** **every price/amount is set in Inter** (`font-sans`), never Bodoni. DESIGN.md already says prices live on Inter; three existing sites drifted to serif (cart page Total, checkout Total, cart drawer Subtotal value). Those three *values* change to `font-sans` (labels such as "Total" stay serif). This is a deliberate edit, not a restyle.
- **D-FONT-3 (acceptable degradation):** if the latin-ext file cannot be vendored, `₦` falls back to `ui-sans-serif, system-ui, "Segoe UI", Arial`, all of which carry U+20A6. Do not block the phase on it, but record it in the verification notes.
- Emails use web-safe stacks only (see Surface 8); `₦` is present in Arial, Helvetica, Segoe UI and the Apple system font.

## Typography

Phase 12 introduces **no new sizes or weights**. The four sizes below are the new-text register. New controls also use the inherited 13px control register (toggle segments, menu chips), and the drawer subtotal / PDP price keep their inherited 20px. Everything else keeps the size it already has (inherited, not re-declared).

| Role | Size | Weight | Line height | Used for |
|------|------|--------|-------------|----------|
| Label / helper | 12px (`text-xs`) | 400; 500 in table headers | 1.33 (Tailwind default) | Form labels (uppercase, `tracking-[0.15em]`), helper text, inline errors, trust line, shipping-zone caption, "auto" pill, admin table headers, last-updated text |
| Body / UI | 14px (`text-sm`) | 400; 500 for admin Total and buttons via existing classes | 1.43 (Tailwind default) | Inputs and selects, summary rows, address blocks, notice body, admin descriptions, order-detail rows |
| Total | 18px (`text-lg`) | 400 | 1.56 (Tailwind default) | Checkout and cart "Total" value (Inter, per D-FONT-2); admin h2 (`text-lg`, serif) |
| Section heading | 24px (`text-2xl`) | 400 (Bodoni, never bolder) | 1.33 (Tailwind default) | "Delivery address", "Order summary" (existing), `/shipping` h2 (existing) |

**Weight declaration: exactly two.** Regular **400** (headings in Bodoni, all body, labels) and Medium **500** (`font-medium`: nav/toggle/button controls, admin Total, table headers, status pills). `font-black` / 900 is **not used anywhere in this phase** (the older specs' h1 convention is superseded; existing pages already render `font-normal`).

**Inherited from existing utilities, not re-declared:** 11px `.eyebrow`/`.kicker` (tracking 0.28-0.3em), 13px controls (`.btn-*`, nav, toggle, `text-[13px] font-medium tracking-[0.01em]`), 16px prose (`/shipping` paragraphs), 20px PDP price (`text-xl`), 30px admin h1 (`text-3xl`), 48px page h1 (`text-5xl`).

**Money rules (apply at every price site):**
- `<Money>` carries **no typography of its own**. The call site's existing wrapper keeps its classes (size, colour, `tabular-nums`); `<Money>` renders unstyled sibling spans inside it.
- All amounts are **Inter**. Where a call site was `font-serif`, switch the value to `font-sans` (D-FONT-2).
- `tabular-nums` stays wherever it already exists (product card, EditRail, PDP, admin and account tables). It is **added** to vertically stacked, right-aligned money values that lacked it, so digits align: cart line totals, cart/checkout/drawer summary values, wishlist price. Whole-unit amounts only (the formatter drops fractions).
- Formatting is owned by `formatMoney` (`en-US`, `narrowSymbol`): `₦45,000`, `$35`. Never hand-format a symbol.

## Color

Black and white only (DESIGN.md "Black and white, nothing else"). Values from `app/globals.css`; every token swaps in `.dark`.

| Role | Light | Dark | Tokens | Usage in this phase |
|------|-------|------|--------|---------------------|
| Dominant (60%) | `#FFFFFF` | `#000000` | `bg-cream` | Page ground, checkout form fields, mobile menu sheet, filter inputs |
| Secondary (30%) | `#F5F5F5` | `#141414` | `bg-cream-dark` | Payment notice panel, admin inputs (existing admin idiom), admin "auto" pill, address block in admin, mobile order cards |
| Accent (10%) | `#000000` | `#FFFFFF` | `ink` / `sepia` (identical) | **Reversal only**, see list below |
| Secondary text | `#4D4D4D` (`ink-soft`) | `#BFBFBF` | `text-ink-soft` | Helper text, captions, inactive toggle segment, trust line |
| Label text | `#595959` (`sepia-deep`) | `#B3B3B3` | `.eyebrow` | Eyebrows only |
| Error / destructive | `#9B2C2C` | see rule | literal `#9B2C2C` (existing, not a new token) | Field errors, server error line, admin save error, invalid-field border |

**Accent (reversal) reserved for:** (1) the **active currency segment** (`bg-ink text-cream`); (2) the primary **Pay now** / **Save rate** buttons (`.btn-primary`, unchanged); (3) the global `:focus-visible` outline and the input focus border (`focus:border-ink`); (4) selected state of mobile-menu currency chips (`border-ink bg-ink text-cream`); (5) admin links and the "Saved" confirmation (existing `text-sepia`). Never used as a resting decorative fill, never to distinguish ₦ from $ (the two currencies are never colour-coded).

**Error colour rule (dark-mode contrast):** `#9B2C2C` measures about 8.0:1 on white but only about 2.8:1 on black, which fails AA for text. So: error text is `text-[#9B2C2C] dark:text-ink`, invalid border is `border-[#9B2C2C] dark:border-ink`, and **an error is never signalled by colour alone** (an explicit message sentence is always present and is the real signal, WCAG 1.4.1). The same pairing applies to the admin save error.

**Calm, not alarming:** the payment-failed/cancelled notice is **neutral** (`bg-cream-dark`, `border-ink/25`, ink text), not error-red. Nothing went wrong that the customer caused, and no money moved. Red is reserved for field-level validation and system errors.

**Third-party marks rule (unchanged):** the Paystack/Stripe names appear as plain text only. No provider logos are introduced (footer `PaymentMarks` is out of scope per CONTEXT Deferred).

## Surface Contracts

**Focal points (visual anchor per primary screen):**
- Checkout: the order-summary **Total** and the **Pay now** button. The address form leads the eye there, and nothing in the form competes with them.
- Cart / drawer: the **Estimated total** row and the checkout button.
- Admin settings: the **rate input** and the impact line ("N products follow the rate").
- Admin product form: the **Price (₦)** field. The $ field and its auto-price helper are visibly secondary.
- Nav: the toggle is quiet and the same weight as ThemeToggle. It is never an anchor.

**Deliberate D-11 refinement:** the visible "₦ NGN" / "$ USD" text is symbol-only ("₦" / "$") between `lg` and `xl` because of nav width, with full codes from `xl`. Accessible names always include the full code.

### Surface 1. Nav currency toggle (`components/CurrencyToggle.tsx`, "use client")

> **Superseded by `12-REGION-SPEC.md` (D-33, 2026-10-21).** The toggle became a region & currency picker; this section is kept for history.

A two-option segmented switch, one control with two renderings. It is a **preference control, not a dropdown**, and matches `ThemeToggle`'s scale: 13px medium type, 24px visual height, no borders, no shadow.

**Placement**
| Breakpoint | Where | Variant |
|------------|-------|---------|
| `lg:` and up (desktop) | Right-hand cluster of the nav bar, **immediately left of `<ThemeToggle />`**, same cluster gap (`lg:gap-5`). Order: [Admin] [Account/Sign in] **[Currency]** [Theme] [Wishlist] [Cart] | `bar` |
| Below `lg:` (phones, tablets) | **Inside the mobile menu sheet**, a final block below the link list (after "Admin" when present) | `menu` |

Rationale for not putting it in the phone cluster: at 320px the wordmark steps down and the right cluster already needs about 100px for three 24px icons plus gaps while each flank gets about 91px; a 64px+ segmented control would break the "wordmark on the true centre line" rule (DESIGN.md Single-Cluster Rule). The sheet is one tap from every page, including `/checkout`. See Assumption A-3.

**`bar` variant (desktop)**
```
<div role="group" aria-label="Currency" className="hidden items-center lg:inline-flex">
  <button type="button" aria-pressed={active === "NGN"} aria-label="₦ NGN, Nigerian naira" ...>
    <span aria-hidden>₦</span><span aria-hidden className="hidden xl:inline">&nbsp;NGN</span>
  </button>
  <button type="button" aria-pressed={active === "USD"} aria-label="$ USD, US dollars" ...>
    <span aria-hidden>$</span><span aria-hidden className="hidden xl:inline">&nbsp;USD</span>
  </button>
</div>
```
| Part | Contract |
|------|----------|
| Segment base | `inline-flex h-6 w-8 items-center justify-center rounded-full text-[13px] font-medium tracking-[0.01em] transition-colors xl:w-14` (32px wide; 56px from `xl:` where the code shows) |
| Pressed segment | `bg-ink text-cream` (reversal; the count-badge idiom). Exactly one segment is pressed at any time |
| Unpressed segment | `text-ink-soft hover:text-ink` |
| Visible text | `lg` to `xl`: symbol only (`₦`, `$`). `xl:` and up: `₦ NGN`, `$ USD` (the strings locked in D-11) |
| Accessible name | `aria-label` **begins with the visible text** (`₦ NGN, Nigerian naira`), so the visible label is contained in the name (WCAG 2.5.3 Label in Name) at both widths. The segments' text spans are `aria-hidden` so the label is not double-read |
| State | `aria-pressed` on each button (true/false). The wrapper is `role="group"` with `aria-label="Currency"` |
| Focus | Global `:focus-visible` (2px ink outline, 2px offset). The group must not set `overflow-hidden` or the outline clips. Outlines are never suppressed |
| Hover | Unpressed only: text goes `ink-soft` to `ink`. Pressed segment has no hover change. No transform, no shadow |
| Size stability | Segment widths are fixed and weight does not change between states, so toggling never shifts the bar |
| Pre-mount | Like `ThemeToggle`, render a same-size placeholder until the active currency is known: `<span aria-hidden className="hidden h-6 w-16 lg:block xl:w-28" />` (64px / 112px = two segments). Pressed state is read from `document.documentElement` `data-currency` (absent means NGN) |

Width safety: at 1024px the bar is already near full (about 900px of content). If, at 1024-1099px, the symbol-only control causes the cluster to wrap or the links to collide, the executor drops the **Admin/Account text links first** to `xl:` visibility, never the toggle. See Assumption A-4.

**`menu` variant (inside `#mobile-nav`, below `lg:`)**
```
<div className="border-t border-ink/10 pb-3 pt-6">
  <p id="currency-menu-label" className="eyebrow mb-3">Currency</p>
  <div role="group" aria-labelledby="currency-menu-label" className="grid grid-cols-2 gap-2">
    <button type="button" aria-pressed=... className="flex min-h-11 items-center justify-center border text-[13px] font-medium tracking-[0.01em] transition-colors ...">₦ NGN</button>
    <button ...>$ USD</button>
  </div>
</div>
```
| Part | Contract |
|------|----------|
| Chip pressed | `border-ink bg-ink text-cream` |
| Chip unpressed | `border-ink/25 text-ink hover:border-ink` (the same chip idiom as `FilterPanel`'s size buttons; sharp-cut, zero radius) |
| Target | `min-h-11` (44px) tall, each chip half the sheet width. Visible text is the full `₦ NGN` / `$ USD`; `aria-label` as above |
| Sheet behaviour | `tabIndex` follows `mobileOpen` exactly like the sheet's links (`-1` when closed). Switching does **not** close the sheet, so the shopper sees the change confirmed in the control; navigating closes it as today |

**Behaviour on switch (both variants), in this order, synchronously in the click handler**
1. If the clicked currency is already active: do nothing (no refresh, no announcement).
2. Write cookie `nostalgia-currency=<NGN|USD>; Path=/; Max-Age=31536000; SameSite=Lax` (+ `Secure` on https; not httpOnly).
3. Set `data-currency` on `<html>` (prices swap **instantly**, CSS only, no reload, no transition, no fade).
4. Update `CurrencyContext`.
5. If on `/shop` or `/collections/*` and the URL has a `price` param, remove it (a range typed in one currency is meaningless in the other; see Surface 6), then `router.refresh()` (or `router.replace` of the cleaned URL, which also refreshes) so the server price sort re-runs. The cart, wishlist, scroll position and open drawer are untouched.
6. Update a visually-hidden status: `<span role="status" className="sr-only">` with "Prices now shown in naira (₦ NGN)." or "Prices now shown in US dollars ($ USD)." This text is empty on mount and is only set by a user action, so nothing is announced on page load.

If cookies are blocked, steps 3-4 still apply for the session (the attribute and context carry it); nothing throws.

**No layout shift:** the toggle's own box never changes size; price text widths differ between `₦45,000` and `$35`, which is inherent and contained, because every price already sits in a `shrink-0` right-aligned slot or its own line (see Surface 2).

### Surface 2. `<Money>` dual-span price (`components/Money.tsx`, no "use client")

Both currencies are in the DOM; CSS shows the active one. Mechanism is fixed by RESEARCH Pattern 5 and not re-decided here. Visual and a11y contract:

| Aspect | Contract |
|--------|----------|
| Markup | Two sibling `<span data-money="NGN">` and `<span data-money="USD">`, **no wrapper element**, so the parent's flex/grid/baseline context is preserved. A `display:none` span creates no box, so it adds no flex gap |
| Hiding rule | Unlayered rule in `app/globals.css` (outside every `@layer`, guarded by a CSS test): `:root:not([data-currency="USD"]) [data-money="USD"], :root[data-currency="USD"] [data-money="NGN"] { display: none; }`. No attribute means NGN |
| Assistive tech | `display:none` removes the inactive price from the accessibility tree and from copy/paste. **Never add `aria-hidden` or `sr-only` tricks on top** |
| Styling | None of its own. Typography comes from the call-site wrapper |
| Props | `amounts: { NGN: number; USD: number }` in minor units; both required |
| Order amounts | **Never use `<Money>` for orders** (account, admin, email). Use `formatMoney(amount, order.currency)` so a toggle can never relabel a historical order |
| `<CurrencySymbol />` | Same mechanism for a bare symbol: `<span data-money="NGN">₦</span><span data-money="USD">$</span>`. Used by the Surface 6 filter prefix |

**Call-site contract (wrapper classes stay exactly as they are today; `<Money>` goes inside):**

| Site | Wrapper (existing, keep) | Notes |
|------|--------------------------|-------|
| `ProductCard` price | `shrink-0 tabular-nums text-sm text-ink-soft` | Name and price share `flex items-baseline justify-between gap-4`; the name may re-wrap by one line when the toggle flips. Accepted (no image or card-box height change) |
| `EditRail` price | `shrink-0 tabular-nums text-sm text-ink-soft` | same |
| PDP price | `mt-4 text-xl tabular-nums text-ink-soft` (a `<p>`) | Stays 20px Inter |
| Wishlist card price | `text-sm text-ink-soft` + add `tabular-nums` | |
| Cart page line total | the existing right-aligned `<span>` + add `tabular-nums` | |
| Cart page / drawer / checkout subtotal and total values | `font-sans` (was `font-serif`), keep size, add `tabular-nums` | D-FONT-2 |
| Drawer line total | `text-sm` + add `tabular-nums` | |
| Free-delivery copy (PDP, TrustStrip, `/shipping`) | the surrounding sentence's own classes | Surface 5 |

**Checkout exception:** `/checkout` shows currency-dependent text ("Free" vs a fee, and the total) so it formats with `formatMoney(amount, currency)` from `CurrencyContext` instead of `<Money>` (Surface 3). It renders only after the session resolves, so there is no server/client text mismatch.

**Tests of record:** in jsdom (no CSS) both spans exist, so price assertions use `getAllByText` or `[data-money]` selectors.

        <p className="mt-2 text-sm text-ink-soft">…</p>

- Items first, address second, summary + Pay last (desktop: summary pinned right). On a phone the Pay button is the last thing, directly after the form, so the shopper reaches it by scrolling forward through the task.
- The Pay button lives in the aside but belongs to the form via `type="submit" form="checkout-form"`: Enter inside any field submits, and there is one validation path.
- The `<fieldset disabled>` locks every field while the redirect is in flight.
- Existing states stay as they are: "Preparing checkout…" (session loading), "Nothing to check out" (empty bag), redirect to `/signin` when signed out.

**Field classes** (RegisterForm's string, adjusted to the 44px target, DESIGN.md's `/25` border and the real error treatment; defined once as a local constant):
```
label:  "mb-1 block text-xs uppercase tracking-[0.15em] text-ink-soft"
        optional suffix: <span className="normal-case tracking-normal"> (optional)</span>
input:  "w-full border border-ink/25 bg-cream px-3 py-3 text-sm text-ink focus:border-ink
         aria-[invalid=true]:border-[#9B2C2C] dark:aria-[invalid=true]:border-ink
         disabled:opacity-60"
select: same string
```
Zero radius (inputs are structural surfaces). Do **not** add `outline-none`: the border-colour shift plus the global focus outline is the entire focus treatment (DESIGN.md). Placeholder text is never used as a label, and none of these fields needs a placeholder.

**Per-field helper and error slots** (same slot, error replaces helper, the RegisterForm pattern):
- Helper: `<p id="{name}-hint" className="mt-1 text-xs text-ink-soft">`. Only Phone has one ("So the courier can reach you.").
- Error: `<p id="{name}-error" className="mt-1 text-xs text-[#9B2C2C] dark:text-ink">`. The input gets `aria-invalid="true"` and `aria-describedby="{name}-error"` (or the hint id when valid).
- Errors push content down; no space is reserved. Nothing animates.

**Client validation (UX only; the server is authoritative and its rules are the source).** Use the same pure `validateAddress` module the server uses so rules and messages cannot drift.
| When | What happens |
|------|--------------|
| On blur of a touched field | Validate that field; show its error inline |
| On change, while a field currently shows an error | Re-validate; the error clears the moment the value is valid |
| On submit with any invalid field | Validate everything, show all errors, **move focus to the first invalid field in DOM order**, do not call the API, do not enter the busy state. No separate error summary (focusing the field makes AT read its label and message) |

## Assumptions, Deviations and Open Items

Everything below was resolved without asking the owner (auto mode). Each item says what was chosen so the checker, planner and executor can challenge it.

| ID | Item | Decision and why |
|----|------|------------------|
| A-1 | Stale design references | `DESIGN.md` + `globals.css` win over the Phase 10/11 specs and over CONTEXT's phrase "cream/ink/sepia, Fraunces/Inter". Those token names still exist but are neutrals; Fraunces and 900 weights are gone. Hex values in this spec come from `globals.css` |
| A-2 | Button radius | DESIGN.md says buttons are zero-radius; `globals.css` `.btn-primary`/`.btn-outline` are `rounded-full`. This spec reuses the classes unchanged and never restates button radius. Inputs, selects, notice, address blocks and menu chips are sharp-cut. Toggle bar segments are pills, matching the count-badge exception. DESIGN.md's button description is out of date (owner may want to correct it; not this phase) |
| A-3 | Mobile toggle placement | In the menu sheet, not the phone cluster (width budget at 320px, wordmark centring). If the owner wants it always visible on phones, the fallback is a single 24x24 symbol button in the cluster that toggles, with the same context/cookie logic |
| A-4 | Desktop bar width at 1024px | Cannot be measured without rendering; my estimate is the bar is already near full there. Symbol-only below `xl` is the mitigation; if it still collides, hide Admin/Account text links below `xl` before touching the toggle. Executor must check 1024, 1100 and 1280 in a browser |
| A-5 | Payment notice | Neutral panel, programmatic focus, not dismissible. Copy asserts "not charged" only for `cancelled` and definitive `failed`. Recommended: map in-flight provider states to a third `?payment=pending` value with its own copy (planner decision; the two required values work without it) |
| A-6 | Price filter on currency switch | The `price` URL param is dropped when the shopper switches (range meaning changes). Sort is kept. No toast |
| A-7 | Derived shipping row | Orders store `total` and item lines, not a shipping amount. Account detail, admin detail and the email show `Shipping` = total minus the sum of line totals (clamped at 0, `Free` when 0), via one pure helper in `lib/orders.ts`, so the numbers add up on screen. Correct for legacy orders too (their stored total already included shipping). If the planner prefers not to add this row, remove it from all three consistently |
| A-8 | "Estimated total" on the cart | Relabelled because shipping is unknown there (D-14). Minimal copy change, no layout change |
| A-9 | Free-delivery copy | Shows the Nigeria threshold labelled "in Nigeria" (RESEARCH Open Question 4); `/shipping` carries both zones |
| A-10 | Fonts | Inter latin-ext must be vendored for `₦` (D-FONT-1); prices are Inter everywhere (D-FONT-2). Three serif price values change to sans. Degradation path D-FONT-3 |
| A-11 | Error red in dark mode | `#9B2C2C` fails AA on black, so error text and invalid borders fall back to `ink` in dark mode with the message always present. No new colour token |
| A-12 | Input border contrast | New inputs use DESIGN.md's `border-ink/25`. A 3:1 non-text contrast for control boundaries (WCAG 1.4.11) is not met by that hairline anywhere on the site today; visible labels identify every control. Flagged for a future site-wide pass, deliberately not changed here to avoid a one-form outlier |
| A-13 | Rate-change guard | `window.confirm` above a 20% change (admin's existing confirm idiom). Threshold is a UX default, trivially changeable |
| A-14 | Provider label source | The Pay button and trust line take the provider name from a server-evaluated prop (`resolveProvider`), because `USD_PAYMENT_PROVIDER=paystack` can reroute dollars. `/checkout` is currently one client component, so the planner will need a thin server wrapper or a server-provided value |
| A-15 | Checkout order | Items, then address, then summary/Pay (mobile reading order). Alternative (address above items) was rejected to keep the reassuring bag review first |
| A-16 | Checkout currency source | `CurrencyContext` (initialised from the cookie/attribute, consumed only after the session resolves) so the page can show "Free" and totals as text; every other storefront price uses `<Money>` |
| A-17 | Admin extras | The "Paid via" column and the products-table footnote are small additions for reconciliation and discoverability; drop either without affecting the contract |
| A-18 | Country list | Nigeria first, then localised names. Which countries are shippable is an owner decision (RESEARCH Open Question 3); the select renders whatever list `lib/countries.ts` provides |
| A-19 | No address prefill | Deferred by CONTEXT (saved addresses); the form always starts empty except Country, which is the shopper's ship-to region (D-33, `12-REGION-SPEC.md`; was Nigeria) |
| A-20 | Browser support | `Intl` `narrowSymbol` and `Intl.DisplayNames` are assumed available in all supported evergreen browsers (RESEARCH Pattern 3); a unit test pins the exact strings |
| A-21 | Next.js detail for the planner | `useSearchParams()` on `/checkout` needs a `Suspense` boundary in Next 14 (the success page already shows the pattern) |
