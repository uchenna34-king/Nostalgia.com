<objective>
Lay the data-layer foundation for Phase 9 (store operations / admin): introduce per-size inventory as a real relation, formalize the order fulfillment fields, sync the schema to SQLite, and expose per-size stock to read paths — all additively, without breaking any Phase 8 consumer.

Purpose: Per-size stock (ADMN-03) and order fulfillment (ADMN-04) both require schema shape that does not exist yet. This plan is the base every downstream Phase 9 plan (admin CRUD, stock-aware catalog filter, order fulfillment UI) builds on. It is the project's first relational break from the JSON-array convention.

Output: `ProductSizeStock` model + `Product.variants` back-relation, `Order.trackingNumber` / `Order.notes` fields with documented status values, a synced `dev.db` + regenerated Prisma client, seed fixtures containing sold-out cases, and a non-breaking `variants` surface on `lib/products.ts`.
</objective>

## Artifacts this phase produces

This plan (09-01) produces the following concrete, downstream-consumable artifacts:

- `ProductSizeStock` Prisma model (`productId` + `size` unique, `stock`, `position`, cascade delete) — the new per-size inventory source of truth.
- `Product.variants` back-relation (`ProductSizeStock[]`) on the existing `Product` model.
- `Order.trackingNumber` (`String?`) field.
- `Order.notes` (`String?`) field.
- In-schema documentation of the `Order.status` allowed value set (pending, paid, fulfilled, cancelled) for app-code allow-list enforcement.
- New `lib/products.ts` export: `ProductVariant` type, plus a `variants: ProductVariant[]` field on the exported `Product` type and its `deserialize` mapping.
- Seed fixtures: per-size stock rows including one fully sold-out product and one partial sold-out size.

The JSON `sizes` column and every existing Phase 8 read path stay intact — `ProductSizeStock` becomes the source of truth for *stock* while `sizes` remains for backward-compatible reads this phase.
