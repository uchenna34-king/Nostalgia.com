<interface_contract>
Both `lib/size-guides.ts` and `components/SizeGuideModal.tsx` are targeted by RED test
scaffolds authored in 10-01. Implement exactly this public surface so the scaffolds pass
without editing them:

- `export type SizeGuide = { category: string; columns: string[]; rows: string[][] }`
  - `category`: the canonical category label (e.g. "Outerwear").
  - `columns`: header labels; index 0 is always "Size" (rendered as the leading column).
  - `rows`: one entry per size row, each aligned 1:1 with `columns`; `rows[i][0]` is the
    size label (XS/S/M/L/XL or similar) used as the row header.
- `export const SIZE_GUIDES: Record<string, SizeGuide>` keyed by the four canonical
  category strings: "Outerwear", "Knitwear", "Tees", "Accessories".
- `export function getSizeGuide(category: string): SizeGuide` — trims + case-insensitively
  matches `category` against `SIZE_GUIDES` keys and returns the match; for an unrecognized
  category it returns the "Tees" guide as a safe default (never throws, never returns
  null/undefined).
- `SizeGuideModal` default export takes props
  `{ guide: SizeGuide; open: boolean; onClose: () => void }` and renders nothing when
  `open` is false.
</interface_contract>

  <action>
    Create `components/SizeGuideModal.tsx` as a `"use client"` island with a default export
    taking `{ guide, open, onClose }` per <interface_contract>. When `open` is false, render
    nothing (conditional mount) so focus management and the entrance transition stay simple.

    Structure: a fixed full-screen backdrop (`bg-ink/40`, `z-[60]`) whose click calls
    `onClose`, plus a dialog panel (`z-[70]`) with `role="dialog"`, `aria-modal="true"`, and
    `aria-labelledby` pointing at a heading element whose id is stable (for example
    "size-guide-heading"). The heading text is `Size guide — {guide.category}`. Include an
    explicit close control: a "×" button, `type="button"`, `aria-label="Close size guide"`,
    with a 44×44px minimum hit target (visible glyph may be smaller), calling `onClose`.

    Render the chart as a semantic `<table>` built from `guide`: a `<caption>` reading
    `{guide.category} size guide`; a `<thead>` row of `<th scope="col">` from `guide.columns`;
    a `<tbody>` with one `<tr>` per entry in `guide.rows`, where the first cell is
    `<th scope="row">` (the size/item label) and the remaining cells are `<td>` measurement
    values. Render all cell values as plain text (React auto-escapes; never use
    dangerouslySetInnerHTML). Wrap the table in an `overflow-x-auto` container so it scrolls
    horizontally on mobile rather than reflowing into stacked cards — this preserves
    row/column semantics for screen-reader users (UI-SPEC §3).

    Presentation: centered `max-w-lg` panel on `sm:` and up over the backdrop; a bottom
    sheet on `<640px` (full-width, anchored to the bottom, rounded top corners,
    `max-h-[85vh]` with internal scroll). Use `bg-cream`, `border border-ink/10`,
    `shadow-xl`. Stay strictly in the locked palette/type (cream/ink/sepia, Fraunces/Inter) —
    introduce no new colors or sizes.

    Implement the FULL mandatory dialog a11y contract from UI-SPEC §3:
    - On open, move focus to the close button (an effect that runs when the panel mounts).
    - Focus trap: intercept Tab / Shift+Tab so focus cycles only among the focusable
      elements inside the panel (compute the focusable set from the panel ref; wrap from
      last to first and first to last).
    - Escape key closes the modal (a keydown listener that calls `onClose`).
    - Scroll lock: add `overflow-hidden` to `document.body` while open and remove it on
      close/unmount (restore the prior value; do not leak the lock).
    - Focus restoration: capture `document.activeElement` when the modal opens and, on close
      by ANY path (× button, backdrop click, Escape), return focus to that element — this is
      what returns focus to the "Size guide" trigger. Guard for a null/detached previous
      element.
    - Motion: entrance is an opacity fade (desktop) / translate-y slide-up (mobile); both
      collapse to an instant show under `prefers-reduced-motion: reduce` via the
      `motion-reduce:` utilities used in Gallery.tsx.
    The modal is a true dialog: it blocks interaction with the page behind it while open
    (that is correct here, unlike the consent banner), but Escape and the close button must
    always provide a keyboard exit so no user is trapped.
  </action>
