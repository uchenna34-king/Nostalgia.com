<objective>
Build the shared review query layer that every Phase 10 reviews surface (PDP read UI, review write action, admin moderation, SEO JSON-LD) consumes, and wire aggregate ratings into the existing product read path — implementing D-01 (verified purchasers only) and D-04 (aggregate rating surfaces everywhere), with D-03 rating validation.

Create `lib/reviews.ts` (Prisma-importing, mirroring the `lib/products.ts` split) holding: verified-purchase eligibility via an in-app scan of the user's own paid/fulfilled orders (no raw JSON SQL), bounded rating aggregation (`groupBy`/`aggregate`, never N+1, never `include:{reviews}`), review upsert + list helpers, and a pure `isValidRating` allow-list. Then merge a `rating {avg,count}` field into the `lib/products.ts` catalog/PDP read path — defaulting missing ids to `{avg:0,count:0}` — while leaving the Phase 8 `buildProductWhere` / stock-aware `where` path byte-for-byte untouched.

Purpose: This is the single source of truth both the reviews UI (10-04/10-05) and SEO JSON-LD (10-11) read from, so the on-page rating and the structured-data `aggregateRating` can never disagree. It turns `tests/reviews.test.ts` (the RED scaffold from 10-01) green.
Output: `lib/reviews.ts` (new) + `lib/products.ts` (rating merged into read paths).
</objective>

  <action>
Create `lib/reviews.ts` as a Prisma-importing module (import `prisma` from `@/lib/db`, and `parseOrderItems` + `OrderItem` from `@/lib/orders`). Export the full surface below. Structure it so the pure helpers never touch the database — only the async functions query — so the pure-logic tests run under jsdom with no DB connection.

Pure helpers (Prisma-free, directly unit-testable):
- `isValidRating(value: unknown): value is 1 | 2 | 3 | 4 | 5` — an explicit 1-5 allow-list mirroring `isValidOrderStatus`: accept only when the value is an integer and a member of a frozen `{1,2,3,4,5}` Set. Reject 0, 6, 2.5, NaN, and any string (per D-03; ASVS V5, mirroring the `isValidOrderStatus` / `buildOrderBy` allow-list idiom).
- `ELIGIBLE_REVIEW_STATUSES` — a readonly tuple of the order statuses that count as proof of purchase: `paid` and `fulfilled` only (per D-01; deliberately excludes `pending` and `cancelled` so an abandoned/unpaid checkout can never yield a "Verified purchase" review — RESEARCH Pitfall 4).
- `purchasedSlugs(orders: { items: string }[]): Set<string>` — pure aggregation: for each order run `parseOrderItems(order.items)` and collect every non-empty `item.slug` into a Set. This is the DB-free core that makes the "hasPurchased slug-match" behavior testable against a fake order array without a database.

Async query helpers (Prisma-importing):
- `hasPurchased(userId: string, productSlug: string): Promise<boolean>` — run `prisma.order.findMany` with `where: { userId, status: { in: [...ELIGIBLE_REVIEW_STATUSES] } }` and `select: { items: true }`, then return `purchasedSlugs(orders).has(productSlug)`. The parameter is a SLUG, not a product id, because the `Order.items` snapshot is keyed by slug only (RESEARCH Pitfall 1) — never attempt to match on a product id, and never issue a raw `json_extract`/`->>` query (breaks at the Phase 11 Postgres migration; cost here scales with orders-per-user via the indexed `userId` FK, never with table size).
- `type RatingSummary = { avg: number; count: number }`.
- `toRatingMap(ids: string[], grouped: { productId: string; _avg: { rating: number | null }; _count: { rating: number } }[]): Map<string, RatingSummary>` — pure: seed the map with an entry for EVERY id in `ids` defaulted to `{ avg: 0, count: 0 }` (the D-04 zero-review default), then overwrite from each `grouped` row using `_avg.rating ?? 0` and `_count.rating`. Exported so the getRatingSummaries zero-default contract is unit-testable without a DB.
- `getRatingSummaries(productIds: string[]): Promise<Map<string, RatingSummary>>` — short-circuit to an empty Map when `productIds` is empty; otherwise run ONE `prisma.review.groupBy({ by: ["productId"], where: { productId: { in: productIds } }, _avg: { rating: true }, _count: { rating: true } })` and return `toRatingMap(productIds, grouped)`. Exactly one bounded query per page/product — never one query per product (no N+1), never `include: { reviews: true }` on a product query.
- `getRatingSummary(productId: string): Promise<RatingSummary>` — single-product variant via `prisma.review.aggregate({ where: { productId }, _avg: { rating: true }, _count: { rating: true } })`, returning `{ avg: agg._avg.rating ?? 0, count: agg._count.rating }`.
- `getReviewsForProduct(productId: string, opts?: { take?: number; skip?: number }): Promise<{ reviews: ReviewWithAuthor[]; total: number }>` — `prisma.review.findMany` where `productId`, `orderBy: { createdAt: "desc" }`, applying `take`/`skip`, with `include: { user: { select: { name: true } } }`; also `prisma.review.count({ where: { productId } })`. Map each row to a `ReviewWithAuthor` (`id`, `rating`, `title`, `body`, `createdAt`, `authorName`) where `authorName` falls back to a neutral label such as "Verified buyer" when `user.name` is null. Selecting only the related user's `name` (never email or id) is a bounded single-relation include for a paginated list — not the catalog `include:{reviews}` over-fetch anti-pattern.
- `getUserReview(userId: string, productId: string): Promise<ReviewRecord | null>` — `prisma.review.findUnique` on the `productId_userId` compound key, so the write UI (10-05) can render the "already reviewed" state and pre-fill the form.
- `upsertReview(input: { productId: string; userId: string; rating: number; title: string; body?: string | null }): Promise<void>` — first assert `isValidRating(input.rating)` and throw on failure (defense in depth, ASVS V5), and length-cap `title` and `body` before persisting (e.g. title <= 120 chars, body <= 4000 chars); then `prisma.review.upsert({ where: { productId_userId: { productId, userId } }, update: { rating, title, body }, create: { productId, userId, rating, title, body } })`. Upsert (not delete-then-recreate) preserves the row id and `createdAt` on edit and enforces one-review-per-user together with the DB `@@unique` constraint (D-01/D-03). This helper performs NO session or eligibility check — that server-side gate lives in the 10-05 Server Action which calls `hasPurchased` first.

Do not add any session/auth logic, React, or UI here — this is the pure data layer. Keep the file Vitest-clean: importing it must not open a DB connection (Prisma connects lazily on first query, so the pure helpers stay DB-free).

- `getCatalog` — set the returned `products` field to `await withRatings(rows.map(deserialize))`.

CRITICAL — do NOT modify `buildProductWhere`, `buildOrderBy`, `parsePriceRange`, `paginationMeta`, the `where` construction inside `getCatalog`, or the `prisma.product.count({ where })` call.
