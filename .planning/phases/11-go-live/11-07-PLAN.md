    edit the dependencies block — 11-04 owns dependencies; this plan owns the vercel-build line only.
    No vercel.json is introduced: Vercel auto-detects the Next.js framework preset and picks up the
    `vercel-build` npm script override automatically, so a config file would add surface for no gain.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo -> hosting | Secrets must live only in the Vercel env store, never in committed files. |
| browser -> app (OAuth) | Google redirects the user back to a registered callback URL; a loose/incorrect URI is exploitable. |
| Stripe -> app (webhook) | Server-to-server callback that mutates order state; endpoint URL + signing secret must be correct and per-environment. |
| local env -> production env | Production secrets (NEXTAUTH_SECRET, STRIPE_WEBHOOK_SECRET) must be distinct from local values. |

## STRIDE Threat Register (ASVS L1 — block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-07-01 | Information Disclosure | Secrets in repo vs. Vercel env store | high | mitigate | Task 2 confirms `.env` is gitignored/untracked before push and enters all keys only in the Vercel dashboard; this plan's sole code artifact (package.json vercel-build line) contains no secret; `.env.example` carries empty placeholders only. |
| T-11-07-02 | Spoofing / Open-redirect | Google OAuth redirect URI + NEXTAUTH_URL | high | mitigate | Task 2 registers the production redirect URI character-for-character with no trailing slash and sets `NEXTAUTH_URL` explicitly on Vercel so OAuth callback, Stripe success/cancel origin, and sitemap all derive from the real origin (RESEARCH Pitfall 4/6) — eliminating the localhost fallback leak. |
| T-11-07-03 | Tampering | Stripe webhook endpoint + signing secret | high | mitigate | Task 2 registers the TEST-mode endpoint against the deployed `/api/stripe/webhook` and sets the production `whsec_` secret (distinct from the local Stripe CLI secret); the webhook route (11-05) verifies the signature over the raw body before mutating order state. |
| T-11-07-04 | Tampering | Per-environment secret reuse (NEXTAUTH_SECRET) | medium | mitigate | Task 2 mandates a FRESH production `NEXTAUTH_SECRET` distinct from local, so a leaked local session-signing key cannot forge production sessions. |
