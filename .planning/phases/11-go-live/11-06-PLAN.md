    Create `app/account/orders/[id]/page.tsx` as an async Server Component. Signature
    `{ params }: { params: { id: string } }` — plain object params (Next 14 App Router),
    exactly like the admin analog.

    Add `export const dynamic = "force-dynamic";`. This route renders one customer's
    private order; `getServerSession` reads cookies so Next should already treat it as
    dynamic, but declare it explicitly so an accidental static/shared cache entry can never
    serve one customer's order to another.

    Authorization, in this order:
    1. `const session = await getServerSession(authOptions)` — the same server-side call
       `lib/admin.ts` and `app/api/checkout/route.ts` use. If there is no `session?.user`,
       `redirect` to `/signin` with a `callbackUrl` back to this order path so the customer
       lands on their order after signing in. Never render order data for an anonymous
       request.
    2. Extract `const userId = (session.user as { id?: string }).id;` — read identity ONLY
       from the server session, never from a query string, header, or prop.
    3. **Critical guard — do this BEFORE the query.** If `userId` is falsy, `redirect` to
       sign in (or `notFound()`) and return; do NOT fall through. Prisma silently drops an
       `undefined` filter value, so a lookup keyed on `{ id, userId: undefined }` collapses
       to `{ id }` and would return **any** user's order that matches the id — a direct
       IDOR. Leave a short inline comment stating this so a future refactor does not delete
       the guard as redundant.

    The order lookup MUST be `prisma.order.findFirst({ where: { id: params.id, userId } })`
    — scoped by **both** the route id AND the session user id in a single query. Do NOT use
    the by-id-only unique lookup the admin analog uses; that ignores ownership. `id` is used
    solely as an equality filter (Prisma parameterises it — not injectable) and is never
    treated as proof of identity.

    On a null result call `notFound()` — let the existing branded `app/not-found.tsx`
    render. Do NOT return a 403, a distinct "this is not your order" message, or any copy
    that differs between "not yours" and "does not exist": collapsing both into one 404 is
    the requireOwner() never-reveal-existence contract (UI-SPEC Contract 4).

    On success, render `<main className="container-x py-16"><OrderDetail order={order} /></main>`
    — reuse the page-level padding established by `/account` and let `OrderDetail`'s own
    `max-w-3xl` set the receipt width. Import `OrderDetail` from `@/components/account/OrderDetail`.

    Do NOT add pagination, a back-nav bar, a reorder/cancel button, or any other UI —
    UI-SPEC forbids surface beyond what it specifies. Do NOT touch `app/account/page.tsx`,
    `OrderList.tsx`, or any 11-03 file.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/account/orders/[id]` Server Component | An anonymous or differently-authenticated visitor requests a page that renders one customer's private order. The route id in the URL is fully attacker-controlled; the session cookie is the only credential. |
| session object → Prisma query | `session.user.id` becomes half of the `where` clause. If it is absent (or dropped), the query's ownership scope collapses. |
| Next.js render cache → response | A cached render of a per-user page could be served to another user. |
| `Order.items` JSON + `item.image` → rendered DOM | Stored data written at checkout, re-read and displayed (thumbnails included) here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-06-01 | Information Disclosure (IDOR) | `/account/orders/[id]` order lookup | critical | mitigate | Query is `findFirst({ where: { id: params.id, userId } })`, scoped by BOTH the route id AND the session user id (Task 2). | T-11-06-02 | Information Disclosure | Prisma `undefined`-filter collapse | critical | mitigate | Explicit falsy-`userId` guard that returns/redirects **before** `findFirst` (Task 2). Without it, `{ id, userId: undefined }` collapses to `{ id }` and returns any user's matching order. Called out inline so it survives refactors. |
| T-11-06-03 | Information Disclosure | existence-revealing error | high | mitigate | `notFound()` (branded 404) for both "not yours" and "does not exist" — never a 403 and never a distinct message. Collapses the two into one code path per the `requireOwner()` precedent (UI-SPEC Contract 4). |
| T-11-06-04 | Spoofing | client-supplied identity | high | mitigate | `userId` is read only from `getServerSession(authOptions)` server-side. The route id is used solely as an equality filter, never as proof of identity; no id is accepted from query string, header, or prop. |
