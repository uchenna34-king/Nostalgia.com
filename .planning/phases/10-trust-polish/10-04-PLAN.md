<objective>
Ship the read-only reviews & ratings UI for TRST-01: a shared `RatingStars` star-glyph
component, the PDP aggregate-rating summary row, an anchored `ReviewList` (first 5 +
"Load more", "Verified purchase" tag, star/title/body/author/date) with a zero-reviews
empty state, and a compact star row on `ProductCard.tsx` (omitted at zero reviews).

Purpose: Reviews are the phase's core trust signal (D-01/D-04). This plan surfaces the
aggregate + individual reviews that 10-03's query layer produced, so shoppers can read
verified-purchase feedback on the PDP and scan star averages across the catalog. It is
read-only — the submit form and eligibility states are 10-05; JSON-LD `aggregateRating`
is 10-11 (both reuse the exact same `product.rating` source, so the on-page number and
structured data never disagree).

Output: `components/RatingStars.tsx`, `components/ReviewList.tsx`, extended
`app/product/[slug]/page.tsx` (summary row + `#reviews` section), extended
`components/ProductCard.tsx` (compact rating row), and `tests/rating-stars.test.tsx`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored review content → rendered PDP HTML | Review `title`/`body`/author name are user-generated content persisted by 10-05; this read UI renders them back to every visitor. |
| merged rating field → SEO (10-11) | The `product.rating.avg` rendered here is the same value 10-11 injects into JSON-LD `aggregateRating`; on-page and structured data must not diverge. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-04-01 | Tampering (stored XSS) | ReviewList / PDP rendering review title, body, author | high | mitigate | Render all review-derived strings ONLY as JSX text nodes so React auto-escapes; no `dangerouslySetInnerHTML` anywhere in the reviews read UI. |
| T-10-04-02 | Information Disclosure | Reviewer identity in the review meta row | medium | mitigate | Display only the first token of `user.name` (fallback "A Nostalgia customer"); never render email, full name, or userId. |
| T-10-04-03 | Denial of Service | Unbounded review set fetched into the PDP + revealed client-side | low | accept | Reviews are verified-purchasers-only (bounded per product); the client reveals 5 at a time. Revisit with server-side pagination only if per-product volume ever grows large. |

No package-manager installs occur in this plan (RatingStars/ReviewList are hand-rolled
Tailwind; `jest-axe` was installed and audited in Wave 0 / 10-01), so no `T-10-04-SC`
supply-chain checkpoint is required here.
</threat_model>
