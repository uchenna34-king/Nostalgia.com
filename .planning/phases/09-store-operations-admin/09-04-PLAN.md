<objective>
Deliver owner-gated product and collection management for the admin back-office: create/edit/delete products (including URL-based image rows, per-size stock, and collection membership) and full collection CRUD, all through Server Actions and `"use client"` form islands, with every storefront-affecting mutation revalidating the relevant public routes so changes appear immediately.

Purpose: This is the no-code control surface the single store owner uses to run the catalog (ADMN-02) and manage per-size inventory (ADMN-03), and it closes the Phase 8 D-11 collection-management deferral (D-06). It is the phase's primary authorization surface — Server Actions are public HTTP endpoints, so `requireOwner()` (inherited from 09-02) is the non-negotiable first line of every action here.

Output: `app/admin/products/**` (list + create/edit routes + actions), `app/admin/collections/**` (list + create/edit routes + actions), and the `components/admin/**` client islands (product form, size/stock editor, image-URL editor, collection picker, tables, collection form).
</objective>

    Export three Server Actions — `createProduct(formData: FormData)`, `updateProduct(id: string, formData: FormData)`, and `deleteProduct(id: string)`.     Add a private `parseProductInput(formData)` helper that extracts each field BY NAME into a typed object: `name`, `slug`, `category`, `description` as trimmed strings; `materials` and `care` as trimmed strings or `null` when empty; `price` via `Number(...)` then reject unless `Number.isFinite` and `>= 0`, storing `Math.round(value)` (integer cents, matching the project's cents convention); `featured` as a boolean from the checkbox value. Return `null` (caller throws `"invalid_product_input"`) when any required field is missing/invalid. Do NOT pass the raw FormData object, nor a spread of it, into the Prisma `data:` argument — every column written is one you extracted by name (mass-assignment mitigation, mirroring the checkout route's `isIncomingItem` discipline).

    Parse repeated sub-rows from FormData into arrays: size/stock rows (each: `size` string + `stock` integer via `Number(...)`, rejected unless `Number.isFinite` and `>= 0`, stored as `Math.floor`) and image rows (each: `url` string + optional `alt` + `position` index). Deduplicate sizes; assign `position` by row order.

    `createProduct`: build the product with nested `variants: { create: [...] }` and `images: { create: [...] }`, connect selected collections via the `Product`<->`Collection` relation (`connect`), AND dual-write `sizes: JSON.stringify(sizeList)` from the same size rows so storefront reads and the checkout route's `sizes` validation stay consistent (the JSON `sizes` column is still a live read path per 09-01). Wrap the create to catch Prisma `P2002` (unique slug collision) and surface it as a field error rather than an unhandled throw.

    `updateProduct`: update the scalar fields, replace child rows with `variants: { deleteMany: {}, create: [...] }` and `images: { deleteMany: {}, create: [...] }`, reset collection membership with the relation's `set: [...]`, and dual-write `sizes: JSON.stringify(sizeList)`. Catch `P2002` on slug the same way.

    `deleteProduct`: `await requireOwner()` first, then `prisma.product.delete({ where: { id } })`. This is a HARD delete and is safe: `Order.items` is a JSON snapshot with NO foreign key to `Product`, so past orders keep their record and cannot be corrupted (D-07, RESEARCH Open Question 2 — verified). Cascade on `ProductImage`/`ProductSizeStock` removes child rows automatically.

    In all three actions, after the write call `revalidatePath` for every affected route: `/admin/products`, `/shop`, `/` (featured grid), `/product/[slug]` (use the `"page"` dynamic form or the specific slug), and `/collections/[slug]` (dynamic `"page"` form) so membership changes reflect. Keep each action returning either void/redirect data or a typed error object the form island can render.
