<objective>
Cut the data layer over from the local file-backed dev database to real Neon Postgres, and land the
complete environment contract for the whole phase.

Four things happen here and nothing else:
1. `prisma/schema.prisma`'s datasource becomes PostgreSQL with a separate `directUrl` for migrations (D-02).
2. `lib/db.ts` is confirmed to need no structural change under the pooled-connection-string approach (D-01),
   with the reason recorded so a future reader does not "fix" it by reaching for a driver adapter.
3. The three existing dialect-incompatible migrations are deleted and replaced by one clean Postgres init
   migration generated against the real empty Neon database, followed by a reseed (D-08).
4. `.env.example` gains all six new variables this phase introduces, as names with empty values (D-09).

Purpose: every other Phase 11 plan (demo-login gate, Stripe webhook, Resend email, order history, deploy)
reads from this env contract and runs against this database. Nothing downstream can be verified until this
plan lands, which is why it is wave 1 with no dependencies.

Output: a Postgres-backed Prisma schema, one regenerated migration folder, a seeded Neon database, and a
committed env contract containing zero credentials.

Non-goals, explicitly: no code that reads any of the six new variables (that belongs to the plans that own
`lib/auth.ts`, `lib/email.ts`, and the webhook route), no Vercel build-command change, no package installs,
no `Order.status` type change.
</objective>
